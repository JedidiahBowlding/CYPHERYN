# CYPHERYN v0.10.0 — Certified Protected-Agent Security and Trusted Egress

This release adds an opt-in execution boundary for protected workloads. It does
not automatically move existing CYPHERYN workers or agents onto the protected
network.

## Security architecture

- Workload identities independent of human sessions.
- Agent capability, destination and data-classification policy enforcement.
- Revocation generations across clients, agents, grants, destinations and policies.
- Short-lived, operation-bound and atomically consumed execution authority.
- A trusted egress proxy that owns the authorized TLS socket.
- DNS answer validation, address pinning and request-body SHA-256 binding.
- Route-limited mTLS gateways between the proxy, protected workload and API.
- Durable execution receipts with replica, correlation and outcome metadata.
- Internal/default-deny protected-agent networking and a read-only pilot.

## Operations and supply chain

- Ordered Alembic migrations through `20261006_egress_proxy_receipts`.
- Three-replica proxy configuration for production.
- Prometheus-compatible proxy metrics and release alert rules.
- Immutable GHCR image publication with commit and version tags.
- Build-provenance attestations, SPDX SBOMs and Trivy gates for all shipped images.

## Enablement

The trusted boundary remains disabled unless the `trusted-egress` profile is
selected. The read-only pilot additionally requires the `trusted-egress-pilot`
profile, provisioned mTLS material, a workload token and an internal/default-deny
network. Direct internet access must never be used as fallback behavior.

## Upgrade warning

Existing installations must verify the legacy egress schema, create and restore-
test a current PostgreSQL backup, stamp `20260930_egress_baseline`, and apply the
ordered migrations before starting the v0.10.0 API in production. Emergency
application rollback retains the additive schema and security evidence.
